# Backend authentication

The gomuks sidecar gates its HTTP API on a username/password that is **entirely separate from the
Matrix account**. gomuks itself says so at the prompt: "This is only used for gomuks and is NOT
your Matrix account."

Two unrelated secrets, worth keeping straight:

| | gomuks web login | Matrix session |
|---|---|---|
| what | `web.username` + `web.password_hash` (bcrypt) | `account.access_token` |
| where | `config.yaml` | `gomuks.db` |
| gates | HTTP access to `127.0.0.1:29325` | requests to the homeserver |

## The fresh-install trap

`pkg/gomuks/config.go:139` — if auth is enabled and either credential is blank, gomuks prompts on
**stdin** via `readline.Line` (`cmd/gomuks/main.go:37`). A Tauri sidecar gets pipes, not a TTY, so
on a machine with no pre-existing config that prompt fails with EOF and the backend exits 9 before
binding its port. Verified 2026-08-27: echo ≤0.3.0 could not start for anyone who had not
previously run gomuks by hand in a terminal.

Note the config key `disable_auth_because_i_want_my_account_to_be_hacked` does **not** avoid this.
The prompt is gated on the Go field `gmx.DisableAuth`, not the config value; the config value only
affects request handling (`server.go:189`, `:249`).

Fixed in 0.3.1: `ensure_backend_config` in `lib.rs` writes credentials before the sidecar spawns.
The password is random and discarded immediately — nothing can log in with it, and nothing needs to.

## How the app authenticates

It mints its own session token, mirroring `signToken` (`pkg/gomuks/server.go:218`):

```
base64url_nopad(compact JSON) + "." + base64url_nopad(HMAC-SHA256(JSON, token_key))
JSON: {"username":"echo","expiry":<unix seconds>}
```

The JSON must match Go's `encoding/json` **byte for byte** or the HMAC will not agree: compact, no
spaces, fields in struct order, `image_only` omitted while false (it is `omitempty`).
`jsontime.Unix` marshals as a bare integer of seconds (`util/jsontime/integer.go:159`).

The token is injected as a `gomuks_auth` cookie through a webview `initialization_script`, so it is
set before any page script runs. `token_key` is generated by gomuks on first load, so the config
can only be read for signing **after** the backend has started.

Pinned by a unit test in `lib.rs` against an independently computed value. If upstream ever changes
`tokenData` or `signToken`, that test is what will notice — the only symptom in the app is the login
form quietly reappearing, which is easy to misread as something else.

## Turning auth off

Set under `web:` in `config.yaml`:

```yaml
disable_auth_because_i_want_my_account_to_be_hacked: true
```

Upstream's name, and the warning is fair. The backend listens on `127.0.0.1:29325`, so with auth
off anything else on the machine — another user account, a page served from another localhost port
— can drive the already-logged-in Matrix session and, via `POST /_gomuks/keys/export`, walk away
with the megolm room keys. Those are portable and permanent: they decrypt history forever, long
after the app is closed. Nothing on the network can reach the port, and malware running as you
already wins anyway (it can read `gomuks.db` directly), so the realistic threat is narrow — but
key export is the part that outlives the session.

## Why upstream's desktop build can disable auth

`desktop/main.go:81` sets `DisableAuth = true`, but that build has **no listening TCP port**: it is
Wails, with the API router mounted as an internal service. Nothing on the machine can reach it. Our
sidecar is a real HTTP server, so that precedent does not transfer.
